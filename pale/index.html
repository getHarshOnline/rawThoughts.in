Pale

Open a repository you already use. Pale shows which review instructions apply and what will change before you install them. Define who is involved, what belongs to whom and what each person or agent may do in one workspace. Pale compiles that description on your own machine for tools such as Claude Code and Codex.

A harness over the tools you already use

Work can span your projects, household, company and clients, and each coding tool you use would otherwise need the same instructions repeated in every session. Pale is a meta harness, a harness over the tools people already use, so each of them draws its permissions and context from one description of your world. It shows where an assignment stands while each person and application keeps its own records and permissions, and it brings you back into the conversation when someone needs a decision.

Among the products, Pale is the part through which the others act, and each of them can also be used without it; Scope then works with Weave. You can configure a workspace and add repository guidance locally today. The live connection to your coding tools is the part being built.

From your description to work you can return to

Take an account review. The customer system holds the account and a reporting tool produces the comparison. A report for the wrong period still needs correction, and the next person should be able to see that and find the original work. Pale gets from your description of the world to that work in four steps; the first two run locally today.

  1. Describe your world

    Say who is involved, which projects, households, organisations and clients you act within, and what each person, agent and application may do. The description is yours, and Pale compiles it without inventing anything. Your agent can help you write it.

  2. Let Pale compile it

    Pale checks the description and fixes it as one version. That version is the boundary your agents work inside: their permissions and their context come from the same source. Before a change takes over, you can see what it would affect.

  3. Let your tools ask at every step

    Before Claude Code or Codex acts, it asks Pale what is allowed and which context the task needs. The customer record stays in the customer system, and the reporting tool keeps the comparison it produces. Routine progress can stay quiet. A request for consent, a conflict or a result that needs review brings you back into the conversation.

  4. Return to the result

    Open the original work and see which decisions are still due. PaleUniverse, the view of your world as Pale compiled it, shows how the work fits into your workspace and where its settings came from. Pale keeps genealogy, the history of context, so a result links back to what it relied on and what followed while each record stays in the system that owns it. When something was wrong, change the description and the next step follows it.

Questions about Pale

How do my coding tools use Pale?

Through a live connection at every step: before Claude Code or Codex acts, it asks Pale what is allowed and what context the task needs, and Pale answers from your compiled description, so every tool works from the same account of your world. A refusal protects anything only where the host enforces it. That connection is the part being built. Today the local tools in the guide add shared coding instructions to a repository and inspect your workspace.

How does my agent help me write the description?

The description is the one thing everything else depends on, so Pale helps you write it. Its editor support and its agent connection use the same compiler. What the editor shows about an edit to your workspace, your agent can review in conversation and get the same answer. Today you can inspect a workspace and compare a proposed edit with the local tools in the guide.

Does Pale replace the systems I already use?

Pale connects the systems you already use rather than taking their place. Each keeps its own records and permissions. When you need the source, Pale takes you back to it.

Can I bring my own setting and systems?

Pale is for your world, not a default one, so you describe your own people, projects and systems in a workspace. A machine binding tells Pale where to find their files and programs. Each application needs its own working integration.

What does PaleUniverse let me explore?

PaleUniverse is for seeing your world as Pale compiled it and following any result back to the description behind it; it is planned for a coming release. Its first views show your World, open the Source behind it and compare a proposed Change. Later views follow work in progress (Now), system health (Doctor) and a result's genealogy: what it relied on, what changed and what followed (Trace).

Where should I start?

Start with a repository you already use. Pale installs shared coding instructions for Claude Code or Codex beside the ones the repository keeps, and shows what a proposed workspace change would affect before you apply it. The Pale guide takes you through choosing a task and using your workspace.
